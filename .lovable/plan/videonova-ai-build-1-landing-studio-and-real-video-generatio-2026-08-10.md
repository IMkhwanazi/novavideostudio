# VIDEONOVA AI — Build 1: Landing, Studio, and Real Video Generation

## What you get in this build

A premium AI video platform with a marketing landing page, secure accounts, a project dashboard, and a real working generation studio. Videos are genuinely generated by AI (Google Veo via Lovable AI) — no fake progress bars, no canned sample clips.

## Stack note

This project runs on Lovable's stack: React + TypeScript + TanStack Start (not Next.js), Tailwind + shadcn/ui, and Lovable Cloud for the Postgres database, auth, file storage, and server functions. That covers everything the spec asked Next.js/Prisma/Auth.js/S3 to do, with no external accounts to set up. Stripe billing comes in a later build.

## 5. Generation studio (`/app/create`)

Four-region creative layout: left prompt/controls, center video canvas, bottom scene strip, right advanced settings.

- Large prompt box with the spec's placeholder and an example prompt chip.
- **Enhance Prompt**: an AI pass that expands vague prompts with subject, environment, camera, lighting, motion, composition, style, and atmosphere. The enhanced prompt is shown and editable before generating.
- Generation modes: Text to Video and Image to Video generate for real this build. Script, Storyboard, Product, and Video to Video appear with an explicit "arriving in the next build" state — no fake output.
- Settings: duration (4/6/8s real; longer durations shown as multi-scene, arriving next build), aspect ratio, resolution (720p/1080p), FPS, visual style, camera, lighting, and a collapsible advanced section with negative prompt.
- Model selector: Fast / Balanced / Cinematic / High Quality, each showing speed, quality, and credit cost. The mapping to actual models lives server-side only.
- Generation summary modal before spending credits: duration, resolution, aspect, model, estimated credits, Generate / Cancel.

## 6. Generation pipeline (the core)

- Clicking Generate validates input, runs content-safety moderation, checks and reserves credits, then creates a `generation_job` row and returns immediately.
- Job progresses through Queued → Processing → Generating → Rendering → Completed / Failed / Cancelled, with the staged copy from the spec ("Preparing your video…", "Generating scenes…", "Rendering video…", "Finalising…", "Your video is ready.").
- The UI subscribes to job updates in realtime, so status changes appear without refreshing. Users can navigate away and come back; jobs keep running.
- On completion the MP4 is downloaded from the provider and stored in private Cloud storage, served via signed URLs. The provider's own link is never persisted (it expires).
- Failure state shows the friendly message plus Retry, Change Settings, Contact Support, and refunds reserved credits.
- Cancel supported while queued or processing.

## 7. Provider abstraction

A `VideoGenerationProvider` interface with `generateVideo`, `getGenerationStatus`, `cancelGeneration`, `extendVideo`, and `generateImageToVideo`. Build 1 ships the Lovable AI (Veo) adapter plus adapter stubs for Runway, Kling, Luma, and OpenAI-compatible video APIs, selected by environment variable. Adding a provider later means writing one adapter file — zero frontend changes. Keys stay server-side always.

## 8. Database (Lovable Cloud Postgres)

Tables this build: `profiles`, `user_roles`, `projects`, `scenes`, `generations`, `generation_jobs`, `assets`, `videos`, `credits_ledger`, `notifications`. Every table gets row-level security so users only ever see their own data, plus foreign keys and indexes on the hot lookup paths. Storage buckets for videos, images, and thumbnails are private with owner-scoped access.

## 9. Credits

Ledger-based: signup grants the Free tier allowance, each generation debits an estimate and reconciles on completion, failures refund. Insufficient balance blocks generation with a "Get More Credits" path (wired to real Stripe checkout in the billing build).

## 10. Quality bar throughout

Skeleton loaders, toasts, optimistic UI, autosave with Saved / Saving… indicator, designed empty states, friendly error states with retry, keyboard-accessible controls, responsive from mobile to desktop, and per-route SEO metadata.

## Explicitly out of scope for build 1

Timeline editor, storyboard drag-and-drop, voiceover, music, captions, templates marketplace, asset manager, brand kit, export modal, Stripe billing, admin dashboard. Build 2 covers editor + timeline + storyboard and voiceover + music + captions, as you selected — the schema and provider layer here are shaped so those slot in without rework.

## Technical notes

- Video generation runs as an async job: a server function creates the job, the client polls/subscribes for status, and a completion step stores the MP4 in Cloud storage before returning a signed URL. Veo supports 4/6/8s clips at 720p/1080p, 16:9 or 9:16 — the settings UI reflects real capability and marks the rest as multi-scene work for build 2.
- Prompt enhancement, moderation, and script logic use Lovable AI (`google/gemini-3.6-flash`) inside server functions.
- All generation endpoints validate with Zod server-side and are auth-guarded at the handler, not just the route.
- Concurrency is capped per project; jobs are started sequentially with backoff on rate limits.
